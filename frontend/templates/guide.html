How Laundry Shop works

Two pages run on data structures written by hand: the service queue and the laundry workflow. This page explains how, in plain terms.

Who this is for

Small laundry shops, self-service laundromats and dormitory laundry rooms where bags are dropped off and collected later. Without a clear line, bags get washed in the wrong order, customers wait longer than they should, and nobody is sure what is ready. Laundry Shop gives the counter one shared line, a price for every bag, and a message to send when the laundry is ready.

Behind the screens it is a Django website with accounts, roles, shops (workspaces), a database and the two data structures below. Both pages call the real classes in backend/dsa/.

The service queue: first in, first out

backend/dsa/queue.py

Customers expect fairness: if Ana's bag arrives before Ben's and Carla's, hers is washed first. That rule is called FIFO, first in, first out.

  1. enqueue puts a bag at the rear of the line.
  2. dequeue removes the bag at the front. This is what Start washing does.
  3. peek reads the front bag without removing it. This is the Next up card.
  4. The line is stored in a deque, which can add at one end and remove from the other in constant time. A plain list would shift every item on each pop(0).

The workflow: a singly linked list

backend/dsa/singly_linked_list.py

The steps a bag goes through (Receive, Wash, Dry, Fold) are kept as a chain of nodes. Each node holds one step and a single next pointer to the following node.

  1. head is the first node and tail is the last. The last node's next is None.
  2. The list keeps a cached _size, updated after every change.
  3. append uses tail to add at the end without walking the chain.
  4. Reading or inserting in the middle means following next from head, one node at a time.
  5. The Data structure inspector on the Workflow page draws the real nodes and their links.

How fast is each operation?

OperationTimeWhy
Queue: enqueue, dequeue, peek, size, is_emptyO(1)The deque works at its two ends and never shifts the other items.
Linked list: prepend, append, remove_at(0), size, is_emptyO(1)head, tail and _size are kept up to date, so no walking is needed.
Linked list: get, index_of, middle insert, middle removeO(n)A singly linked list has no index, so it follows next from the head.
Linked list: remove the last nodeO(n)You must find the node before it, and nodes only point forward.
to_list() and loading a saved snapshotO(n)Every item is visited once.

A whole web request is not O(1) just because the queue operation is. The request also loads the saved data, saves it again and renders a page.
